# ai-inventory

Grid inventory: items have a size in cells and can be turned; player inventory, ground drops, stashes, vehicle trunk and glovebox, shops, crafting benches, weapons (ammo in metadata, basic attachments), usable items. Depends on ai-core (characters, money, jobs, gangs, prompts, admin panel) and its own table through `@aicore-fivem/mysql`. Stands in for `ox_inventory` and `qb-inventory`.

## Decisions

- Cells are slots: a stack sits at its top-left cell (`slot`, 1-based, row-major) and covers `w x h` cells, so slot-based APIs (ox, qb) keep working. Placement rules live once in `resource/common/grid.ts` (server authority, NUI highlight).
- Every inventory has the panel's column count (default 8); a panel change of the columns or of a kind's rows / weight limit re-lays every loaded inventory and sends its viewers `EVENTS.layout` (`Inventory.relayout`), so open screens change at once; only rows and the weight limit differ. `Inventory.rebuild` (load and every re-lay) moves a stack that no longer fits at its slot to the first free place and, when none is left, adds rows to that inventory until it fits (an item wider than the columns both ways gets its own rows), so nothing is lost, hidden or drawn on top; the extra rows stay until the next re-lay or load. `Occupancy.mark` clips at the grid edge, never wrapping into the next row.
- Server memory is the truth (`server/registry/registry.ts`): player inventories with the character (a holder count per id; it leaves memory when the last holder unloads), stashes and trunks loaded on first open and unloaded after 5 idle minutes, drops and temporary stashes never stored. A dirty flush every 30 s writes one multi-row upsert; also on unload, resource stop and txAdmin shutdown. Each inventory is one JSON row rewritten whole (~5 KB per player, 2,048 dirty players ~10 MB per flush): accepted; per-slot rows pay off only for much larger inventories. Every query waits for `prepareDatabase()` (`server/registry/repo.ts`), so loads right after a restart never race the table setup.
- Every change goes through `Inventory` (`server/inventory/inventory.ts`, stack and cell changes in its base `slotGrid.ts`), which sends one delta per tick of the touched slots to the inventory's viewers. Callers never push.
- Client actions pass `reachable()` (`server/access.ts`): only the player's own inventory or the one he has open, re-checked against its point / vehicle on every action. Place access is the record's access fields (`Place.access`, lib `readAccess`; panel `ACCESS_FIELDS` / `accessFields()`): lib `online.allows` on the server, `allows` in the client's `canShow`; a script stash's ox `groups` become its jobs at a minimum grade.
- An owned vehicle's (`ai:owned` state bag) trunk / glovebox is stored as `trunk:v<id>` / `glovebox:v<id>` by its ai-vehicles id (`ai:vid` state bag), so a fake or changed plate keeps the items; scripts still address it as `trunk:<registered plate>` (a registry alias set on open from ai-vehicles' stored plate, never the plate on the car, dropped when the inventory unloads). Loading it from the database first moves an old `trunk:<registered plate>` row over (`UPDATE IGNORE`); that move is shared by concurrent openers, each waits for it before loading (else one loads an empty trunk and its save overwrites the moved row). An owned vehicle without an id falls back to `trunk:<PLATE>`. Any other vehicle gets `trunk:tmp:<entity>`, never stored and removed on `entityRemoved`, so an unowned car with the same plate never opens or shadows an owned car's trunk (`server/open/vehicleInventory.ts`).
- Items, shops, stashes, benches and settings are panel content, all `sync: "all"`; shops, stashes and benches are per-record views (`records`: one edit re-reads one record; client points through lib `RecordObjects`), items, rarities and settings are parsed again whole on a change; recipe ingredients are one text (`"scrapmetal:3, paperbag:1"`) because the panel's list rows hold only text, number and switch.
- Weapon ammo lives in the weapon's metadata; the client reports only lower ammo, reloading takes ammo items on the server. A held weapon is found again by its `serial` when it moves. Weapons not given by ai-inventory are removed from the ped (`onCache("weapon")`).
- Item use with an animation runs on the server (`playUse` in `server/use.ts`): lib `progressFor` plays the use kind's animation (`USE_ANIMS` in `common/items.ts`) under ai-core's bar and counts only after 80 % of the item's time; the stack is consumed only if the slot still holds the same item (serial) afterwards. One use at a time per player.
- Stacks are equal when name and metadata match: `metaKey` is a JSON text with keys sorted at every depth (nested `info` counts), used by merges, `count` and `remove`.
- Drops (`server/drops.ts`): a 64 m cell grid; a client knows only the drops of the 7 x 7 cells around its player (snapshot at character load with `reset`, then put / remove as drops come and go, and when a 2 s check finds the player in a new cell; the check runs only while drops exist). Lists over 100 points go as several reliable events (never latent: a latent snapshot could arrive after a later remove). A new drop is limited to one per second per player, the panel's live cap per character (`drop.maxPerPlayer`, default 10) and 50 per cell; adding to a drop within 1.5 m is free. Crafting results and script drops (`CustomDrop`) skip the limits.
- Quick slots are their own five slots of the player inventory (owner decision: grid cells never stand in for them): slot numbers `HOTBAR_FIRST` (9001) to 9005 in `common/grid.ts`, outside every grid, each holding one stack of any size; their weight counts, they cover no cells (`Inventory.coveredAt` / `fitsAt`, `put` / `take` skip the grid for them; the NUI grid leaves them out). The quick slots under the equipment column are drop targets and drag sources (`data-hotbar`, `web/src/features/panels/QuickSlots.tsx`); while the pointer is within 5vh of their row (`data-quick-slots`) the drag ghost shrinks to a slot's size. Keys 1-5 use them. F2 opens the screen, Tab shows / hides the five as a bar at the bottom while it is closed (`Hotbar` in `client/screen.ts`: the player's deltas keep reaching the NUI while it shows; drawn as tgiann-inventory's hotbar in `web/src/features/panels/Hotbar.tsx`). The GTA weapon wheel and its keys are disabled while the panel's `noWeaponWheel` is on (`client/wheel.ts`, lib `controls`).
- The screen follows tgiann-inventory's grid (Tarkov) layout: equipment (clothes in two columns around the character) and quick slots on the left, the player's card next to it, the second inventory's card on the right, the name on top. Cards are joined grids whose cell size follows the column count (`lib/cell.ts` `setCellFor`, about 52vh wide). Item boxes take their rarity's colour (panel Rarities tab, `rarity` on an item through the panel's `records` link); clothes icons are tgiann's SVGs drawn as CSS masks. The clothes take pieces off and put them back on with a click (`client/clothes.ts`, pieces in `common/clothes.ts`): the "off" drawables are base-game values per freemode sex, the worn piece is kept by collection name + local index and only this client changes the ped (ped clothes replicate). Not items: nothing is stored, a new ped (model change) forgets what was kept.
- The character between the clothes columns is a game-drawn local copy of the player (`client/worldPed/`, tgiann-inventory's technique): the NUI reports the area's screen shares (`worldPed` callback, again on resize and on the show / hide switch, kept in the NUI's localStorage), the copy (`ClonePedToTarget`) stands at a depth where its scaled body (0.2) fills that area, faces the camera through `SetEntityMatrix` with the camera's up axis, smoothed over 5 frames, lit by a light in front; the real ped is locally invisible. On foot a scripted camera (lib `ScriptCamera`) holds the view where the game camera was while the copy shows (`holdView`): the clothes animations move the real ped and its follow camera, and a copy placed from last frame's camera wobbles; in a vehicle the game camera stays. A clothes change copies only the changed components and props onto the copy after the animation (`refresh`), never a second `ClonePedToTarget` (it resets the copy's pose). With the switch off the area shows tgiann's body silhouette (`web/src/features/panels/PedSilhouette.tsx`). The screen has no blur (owner decision).
- Dropping onto the ground panel (nothing open next to the player's own) makes the player watch that drop: the server sends its snapshot (`EVENTS.ground` -> NUI `ground`) and deltas follow; when it empties `forceClose` brings the ground panel back. With a shop or bench open the client refuses it with `EVENTS.close`.
- Item images come from ox_inventory (GPL-3.0, `NOTICE.md`), converted to lowercase file names; default items from its `data/items.lua` and `weapons.lua`.

## Contracts

- Net events and callbacks: `resource/common/events.ts`; wire and NUI shapes: `resource/common/nui.ts`, their parsers `common/nuiParsers.ts`; panel content `common/content.ts` (records and their readers `common/places.ts`, settings `common/settings.ts`). Replies are the shared `ActionResult` (lib `fail` on the server, `callAction` on the client, which shows the refusal itself).
- Server exports (own): `AddItem`, `RemoveItem`, `GetItemCount`, `CanCarryItem`, `CanCarryItems(inv, items)` (`fitsAll`: summed weight, shared stack room, one scratch grid), `GetItems`, `RegisterUsableItem(name, handler)`, `RegisterStash`, `OpenInventory`, `ClearInventory`, `Items`, `GetWeight`, `SetMetadata(inv, slot, metadata)`, `SetMaxWeight(inv, grams)` (a loaded inventory's limit through `Inventory.relayout`, so open screens follow; the panel's next limit change or a reload resets it; ox `SetMaxWeight` uses it too), `RegisterShop(name, label, [{ name, price }])` / `OpenShop(source, name)` (script shops, `server/scriptShops.ts`: no place, shown with `EVENTS.scriptShop`; buying is allowed only while that player has it open, paid from cash then bank; a panel shop of the same id wins). Other ai-* scripts never call them: they go through ai-core's inventory layer, whose ai-inventory adapter uses these (`docs/compat/inventory.md`); never call ai-core's inventory exports from here (loop). Client: `OpenInventory`, `CloseInventory`, `GetItemCount`, `HasItem`, `GetPlayerItems`.
- ox_inventory and qb-inventory exports: `server/compat/ox/`, `server/compat/qb.ts`, client ones in `client/exports.ts`; what they answer and leave out: `docs/compat/ox_inventory.md`, `docs/compat/qb-inventory.md`.
- Client local event `ox_inventory:itemCount (name, total)` after each change of the player's own totals (`client/itemCounts.ts`; ox scripts and ai-core's client inventory layer listen), client export `GetPlayerItems()`.
- Server local event `ai-inventory:usedItem (source, name, slot, metadata, status)` after every use (`status` = the item's hunger / thirst / stress values); `ai-inventory:itemsChanged` after a panel edit of the items (ai-core re-reads the definitions and sends clients what changed).
- Table `ai_inventory_inventories` (id, items JSON `{ v: 1, s: [[slot, name, count, metadata, rotated]] }`).
- Log channels `moves` (off by default), `drops`, `gives`, `purchases`, `crafting`.

## Pitfalls

- Bun cannot resolve tsconfig path aliases under a folder named `[ai]`: the bench is bundled by `bench/run.ts` (`bun run bench`) with `common/*` resolved there.
- oxlint finds no files in a resource without its own `.git`: it applies the server repo's `.gitignore`, which ignores `resources/[ai]/`.
- NUI grid maths uses only the cell pitch `CELL_VH` (`web/src/lib/cell.ts`); boxes are drawn inset by half of `CELL_GAP_VH`. The drag ghost is always held from the centre of its cell area (`w x h` cells as turned, in `DragState`): the drop cell is the pointer minus half that size, rounded, so never store a grab offset. Empty cell boxes are drawn only for free cells, so a big stack shows no cell lines through it.
- A Radix `ScrollArea` inside a card that only has `max-height` scrolls only because its root is a flex column and the viewport `min-h-0 flex-1` (`components/ui/scroll-area.tsx`): a `height: 100%` viewport grows to its content there and the wheel does nothing. While dragging, the band 6vh inside a scrolling grid's top / bottom edge scrolls it (`drag.ts`, a frame loop only while in the band), and any scroll under a still pointer re-targets the drop.
- The NUI gets no `contextmenu` event: the item menu opens on `mouseup` with button 2. Game keybinds do not fire while the NUI has focus: the NUI closes on Escape or the open key it got with the `open` message (both on key release). The key comes from lib `Keybind.currentKey`, which falls back to the registered key for keys GTA names by an icon code (F1-F12, Tab).

- The open key's trunk is lib `nearestVehicle(8, { filter: atBack })`: the closest vehicle whose back the player stands at, so between two cars parked nose to tail the one behind the player opens (`client/open.ts`).

## Entry points

- Grid rules: `resource/common/grid.ts`; one inventory `server/inventory/` (`inventory.ts`, cells and stacks `slotGrid.ts`, add planning `addPlan.ts`, per-tick deltas `deltas.ts`, metadata keys and serials `stacks.ts`); loading, saving, viewers `server/registry/` (`index.ts` runs the 30 s flush, the database setup and the stop / shutdown saves); the script API under every export layer `server/api/`; panel `server/schema/` (one file per tab).
- Moving and swapping: `server/move.ts`; move / drop / give callbacks `server/actions.ts`; use, weapons `server/use.ts`, `server/weapons.ts`; shops and crafting `server/shop.ts`; opening `server/open/` (`open.ts` checks, `vehicleInventory.ts` trunks and gloveboxes).
- Client: screen and NUI messages `client/screen.ts` (the `profile` message: name and clothes), clothes column `client/clothes.ts`, Tab key and context `client/open.ts`, shop / stash / bench points `client/places.ts` (lib `Points` from `RecordObjects`; a shop's blip is its record's `blip` switch and `blipStyle`, lib `readBlipStyle`, defaults copied from qb-shops per shop: 24/7, LTD and liquor 52 at 0.6, Ammu-Nation 110 at 0.6, hardware 402 and the weed shop 140 at 0.8, colour 0; stashes and benches have no blip), ground bags `client/drops.ts` (a `Zones` area spawns the bag prop, a `Points` entry opens it), held weapon `client/weapons.ts`.
- NUI: root `web/src/App.tsx`, grid and drag `web/src/features/grid/`, panels `web/src/features/panels/` (one component per file); browser preview `bun run webdev` with `?view=stash|ground|shop|bench`.
- Scale numbers: `bun run bench` (`bench/inventory.bench.ts`, natives stubbed): 100k inventories x 6 stacks 1.6 s / +340 MB, 1M 16 s / +1.7 GB; one add on a full 14 x 50 grid ~80 µs; a move ~13-21 µs; 2,048 players with 10k drops: new drop ~14 µs, merge lookup ~2-4 µs, join snapshot ~1 KB, every player changing cell in the same pass ~60-75 ms (with 100k drops: 10 KB snapshot, ~300-400 ms; the per-character cap keeps real counts near 20k at most).
